# Контракт API

Базовый путь: `/api/v1`. Дополнительно поддерживаются путь без префикса и
`/1cTema/hs/api/v1`. Все защищенные запросы требуют заголовок
`Authorization: Bearer <TEMA_API_TOKEN>`.

## Маршруты

| Метод и путь | Назначение |
| --- | --- |
| `GET /counterparties`, `GET /counterparty/{id}` | Список и карточка контрагента |
| `POST /counterparty`, `PATCH /counterparty/{id}` | Создание и изменение контрагента |
| `GET /nomenclatures`, `GET /nomenclature/{id}` | Список и карточка номенклатуры |
| `POST /nomenclature`, `PATCH /nomenclature/{id}` | Создание и изменение номенклатуры |
| `GET /orders`, `GET /order/{id}` | Список и карточка заказа |
| `POST /order`, `PATCH /order/{id}` | Создание и изменение заказа |
| `GET /invoices`, `GET /invoice/{id}` | Список и карточка счёта |
| `POST /invoice`, `PATCH /invoice/{id}` | Создание и изменение счёта |
| `POST /invoice/{id}/payment` | Регистрация оплаты счёта |
| `GET /acts`, `GET /act/{id}` | Список и карточка акта |
| `POST /act` | Создание акта на основании счёта |
| `GET /invoice/{id}/pdf`, `GET /act/{id}/pdf` | Печатные формы УНФ |
| `GET /order/{id}/kp/pdf` | КП штатной подсистемой печати УНФ |
| `GET /order/{id}/specification/pdf` | Спецификация из сохранённых строк заказа |

Списки используют оболочку `total`, `page`, `limit`, `data`. Поля фильтров и
допустимые значения статусов оплаты см. в `tema_api/service.py`.

## Минимальные тела создания

```json
{
  "date": "2026-11-23",
  "customer": { "id": "000000001" },
  "items": [
    { "product_id": "000000001", "quantity": 1, "price": 1000 }
  ],
  "comment": "Заказ из внешней системы"
}
```

Счёт создается по `order_id` и `date`. Акт — по `invoice_id` и `date`. Контакты
контрагента передаются в `contact_info`; запись выключена по умолчанию в примере
конфигурации и требует отдельной проверки целевой базы.

Для POST/PATCH передавайте стабильный `Idempotency-Key` для одной бизнес-операции.
При повторе с тем же ключом и тем же телом вернётся сохранённый результат; то же
ключевое значение с другим телом даст `409`. Если соединение оборвалось после
фиксации операции в 1С, запись может остаться `pending`; сначала сверьте базу,
не повторяйте создание с новым ключом вслепую.
