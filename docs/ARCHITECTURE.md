# Архитектура

## Поток запроса

```text
Внешний клиент
    │ HTTPS + Bearer
    ▼
Python API (порт 8770)
    ├── OData v3 ───────────► 1С:УНФ
    └── внутренний HTTP ────► HTTP-расширение TEMA_API ─► штатная логика УНФ
```

Python выполняет публичную Bearer-аутентификацию, проверяет тела запросов,
нормализует ответы УНФ, журналирует идемпотентность операций записи и маршрутизирует
операции. Пароль 1С и токен API клиенту не выдаются. При внешней публикации TLS
должен завершаться на обратном прокси; прямое открытие локального порта наружу
не является рекомендуемой конфигурацией.

## Граница OData и расширения

| Через OData | Через HTTP-расширение |
| --- | --- |
| Чтение/простые записи контрагентов и номенклатуры | Заказ с заполнением табличной части средствами УНФ |
| Списки заказов, счетов и актов | Счёт на основании заказа; акт на основании счёта |
| Чтение данных документов с простыми связями | Платёж и проведение документа |
| Подсчет данных списка | Штатная печать счёта, акта и КП |
| Новая спецификация строится Python из сохранённого заказа | Контакты контрагента через процедуры БСП |

Для ссылок в API `id` справочника — код, `id` документа — номер. GUID принимается
вместо кода/номера. При неоднозначном номере сервис отвечает конфликтом, а не
выбирает документ случайного года.

## Связь сделки amoCRM

Расширение хранит соответствие идентификатора документа и числового `amocrm_lead_id`
в отдельном регистре `TEMA_СвязиСделок`. Это хранение идентификатора; отправка
вебхука или вызовы amoCRM в проект не реализованы.
