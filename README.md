# Интеграция ТеМа с 1С:УНФ

Отдельный проект API-интеграции ТеМа с 1С:УНФ. Здесь находятся Python-фасад,
исходники HTTP-расширения 1С `TEMA_API`, тестовая веб-форма, локальные unit-тесты
и документация. Python-пакет можно запускать отдельно от других приложений.

## Состав

- `tema_api/` — Python API, OData-клиент, маршрутизация, печать спецификации,
  скрипты работы с расширением и его исходники.
- `tema_api/bridge/` — XML/BSL-выгрузка расширения `TEMA_API`.
- `tema_api/web/` — форма ручной проверки API.
- `tests/` — изолированные unit-тесты с поддельными OData/HTTP-клиентами.
- `docs/` — архитектура, контракт, развертывание, проверки и состав исходных
  материалов.
- `assets/fonts/` — шрифты Ubuntu и лицензия для PDF-спецификации.
- `config/settings.example.json` — пример конфигурации без паролей и ключей.

## Быстрый старт

Нужны Python 3.11+ и доступ к тестовой базе УНФ с опубликованным OData. Для
генерации PDF спецификации устанавливается ReportLab:

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item config\settings.example.json config\settings.local.json
$env:TEMA_API_TOKEN = '<случайный секрет не короче 32 символов>'
.\.venv\Scripts\python.exe -m tema_api.server --config config\settings.local.json
```

Перед запуском заполните локальный `settings.local.json`: адрес OData, пользователя,
пароль, адрес HTTP-сервиса расширения, если он опубликован, и настройки организации.
`settings.local.json` исключен из Git. Не вставляйте токены и пароли в исходники.

Сервис по умолчанию слушает `127.0.0.1:8770`, API имеет префикс `/api/v1`,
а `/health` проверяет только Python-процесс. Пример запроса:

```powershell
Invoke-RestMethod http://127.0.0.1:8770/health
```

Подробные инструкции: [Развертывание](docs/DEPLOYMENT.md),
[контракт API](docs/API.md), [архитектура](docs/ARCHITECTURE.md).

## Текущий статус

Решение разработано и проверялось на тестовой базе УНФ 3.0.2.215. Зафиксированы
проверки справочников, заказов, счетов, актов, оплат и PDF, однако они не являются
подтверждением работы в промышленной базе. Публичный amoCRM-виджет, СБИС,
webhook amoCRM и промышленное внешнее развертывание не входят в проверенный объем.
См. [статус и ограничения](docs/STATUS.md).
